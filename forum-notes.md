# Forum conventions worth knowing

Context notes on how trading-forum threads are typically run, useful for
judging how much to trust a given post (e.g. whether a "call" was made in
real time or is being presented with hindsight bias).

## "EURUSD only" thread rules (forexfactory.com)

A community-rules OP for a long-running EURUSD-focused thread. Relevant
rules, since they set the bar for whether a claimed trade call in this
kind of thread is verifiable:

- **Real-time posting requirement**: if a member posts a signal, they
  must post the entry/exit at the time it happens (~3-5 min tolerance).
  This is the norm that made it possible to check MzansiObi's BTCUSD call
  in [`trading-journals.md`](trading-journals.md) against real price
  data — the timestamp on the post is the actual decision time, not a
  retrofit.
- Strictly single-pair focus (EURUSD only, off-topic pairs get
  downvoted/hidden) — a common structure on this forum, mirrored by the
  single-asset "generals" seen elsewhere (e.g. the BTCUSD, GME, XMR, XRP
  threads already in this repo).
- No after-the-fact profit flexing, oversized/colorful attention-seeking
  formatting, or lecturing from newcomers — enforced by the moderator
  directly.
- Notably permissive on emotional venting: members are explicitly allowed
  to curse or offend others during a bad trading day, provided they
  later acknowledge it and apologize — an explicit trade-off favoring
  emotional release over strict politeness, framed as building
  community cohesion.

## Takeaway for reading forum "calls"

A thread enforcing real-time posting (like this one) makes claimed trade
calls independently checkable against market data. A thread that doesn't
enforce this (or that allows edited/backdated posts) should be treated
with more skepticism — always check the actual timestamp and historical
price data before trusting a "called it" claim, as done for the BTCUSD
case study.
